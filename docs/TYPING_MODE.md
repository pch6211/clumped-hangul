# 직접 타이핑(타입건틀렛식) UI — 타당성 & 설계 옵션

## 요청
"타입건틀렛처럼 화면에서 직접 타이핑하면 그 글자가 나오는 방식이 가능한지 점검."

## 결론: 가능하다 (이미 절반은 구현돼 있음)
이 앱은 **이미** `#mainText` 입력 내용을 캔버스에 **큰 클럼프 한글로 라이브 렌더**한다
(타입건틀렛의 핵심 동작). 한글 IME 조합도 textarea라 자연히 처리된다.
남은 마찰은 단 하나: **"입력창(좌상단 텍스트 박스)을 먼저 클릭해야" 한다**는 것.

## 핵심 설계 긴장 (사용자 결정 필요)
"아무 데서나 바로 타이핑"을 기본으로 만들면 **단일키 단축키(A·T·R·B·M 등)와 충돌**한다.
현재 구조상 입력창이 포커스되면 단축키 핸들러가 자동으로 비활성화되기 때문
(`main.js` 전역 keydown 게이트). 즉 둘은 동시에 가질 수 없고, 트레이드오프를 골라야 한다.

## 옵션
1. **몰입 타이핑 모드 토글 (현재 프로토타입으로 구현·배치)** — 비파괴.
   - 백틱(`` ` ``)으로 진입 → 입력창 포커스 + 단축키 자동 일시중지 + 하단 힌트.
   - `Esc`로 종료 → 단축키 복귀. 기존 동작 일절 변경 없음. 영구 UI 추가 없음.
   - 구현: `src/typing-mode.js` (독립 모듈).
2. **상시 type-anywhere + 단축키를 보조키로 이동** — 가장 타입건틀렛다움.
   - 클릭 없이 어디서나 타이핑되게 하고, A/T/R/B/M 등은 `Cmd/Alt+키`로 이동.
   - 장점: 가장 직관적. 단점: 기존 단축키 UX 변경(학습된 사용자에 영향).
3. **전용 풀스크린 스페시멘 뷰** — 큰 입력 오버레이 + 중앙 대형 렌더, 감상/촬영용.
   - 별도 화면으로 진입/이탈. 메인 UX와 분리.

## 권장
1번(프로토타입)을 출발점으로 두고, 디자이너인 사용자와 함께 최종 UX를 다듬자.
type-anywhere(2번)를 원하면 단축키 보조키 매핑을 같이 결정하면 된다.

## 지금 사용법 (프로토타입)
- 화면(입력창 밖)에서 백틱(`` ` ``) → 직접 타이핑 모드. 바로 입력하면 글자가 큰 클럼프로 등장.
- `Esc` → 종료. 단축키 다시 사용 가능.

## 프로토타입 상태 / 알아둘 점
- 앱의 텍스트 입력창(#mainText)은 **첫 상호작용 시 지연 생성**되고 PC/모바일로 분기된다
  (이는 분할 전 원본과 동일한 동작 — A/B로 확인, 회귀 아님). 그래서 프로토타입은
  `#mainText → #mobileText → 임의 textarea` 순으로 활성 입력창을 탐색한다.
- 앱이 아직 입력창을 만들기 전(완전 첫 로드 직후)이라면 안내 힌트만 뜬다.
  화면을 한 번 클릭/타이핑해 앱을 깨운 뒤 백틱을 쓰면 된다.
- 최종 UX(옵션 1~3)는 디자이너인 사용자와 함께 결정 후 다듬는 것을 전제로 한 출발점이다.
